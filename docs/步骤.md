### 第3步：创建 Issue（逐个创建）

```
仓库 → Issues → New Issue
```



每个 Issue 填好 Title，右侧选择 **Assignee** 和 **Milestone**。

gmy在GitHub创建issue

> **提示**：Issue 描述里可以贴一段功能说明，例如 #2 写：
>
> ```
> Player 类需包含：name、currentRoom、bag、currentLoad、maxCapacity、attack、defense、health
> 方法：takeItem()、dropItem()、useItem()、hurtBy()、moveTo()
> ```

------

### 第4步：创建 develop 分支

```
仓库 → Code → branch 下拉框 → 输入 "develop" → Create branch develop from main
```



------

### 第5步：保护 main 分支（禁止直接 push）

```
仓库 → Settings → Branches → Add branch protection rule
```



- Branch name pattern: `main`
- 勾选：**Require a pull request before merging**
- 勾选：**Require approvals**（设为1）

这样以后任何人不能直接 push main，必须走 PR。

------

### 第6步：推文档到 GitHub

你已经写好了4个文档，首次推上去：

在项目根目录执行：

```
# 先把文档加入 staging
git add README.md REPORT.md docs/zuul-api.md .github/workflows/maven.yml

# 提交
git commit -m "docs: 初始化项目文档、API文档和CI配置"

# 推送到 GitHub
git push origin main
```



------

### 第7步：成员各自 clone + 建立 feature 分支

告诉 zy 和 lfk 在自己电脑上执行：

```
# clone 仓库
git clone https://github.com/wutcst/kai-fa-kskblzdjd.git
cd kai-fa-kskblzdjd

# 创建并切换到 develop

然后 **lfk（后端）** 执行：

```



**zy（前端）** 执行：

```



**gmy（你）** 执行：

```
git checkout -b feature-game-core develop
git push origin feature-game-core
```



------

### 第8步：开发中提交规范

每人开发完一个模块后：

```
git add .
git commit -m "feat: 实现 Player 类及背包系统"
git push origin feature-xxx
```



然后在 GitHub 上：

```
Pull requests → New pull request
base: develop  ←  compare: feature-xxx
```



PR 描述里写上 `Closes #2`（自动关联对应 Issue），右侧 **Reviewers** 选另一位成员。

------

### 第9步：Code Review 流程

Review 的人：

1. 去 **Pull requests** → 点开 PR → **Files changed** 查看代码
2. 没有问题就点 **Review changes** → **Approve**
3. 然后点 **Merge pull request** → **Confirm merge**

------

### 第10步：最终发布

所有 v3.0 功能都合入 develop 后：

```
Pull requests → New pull request
base: main  ←  compare: develop
```



同样 Review → Merge。
